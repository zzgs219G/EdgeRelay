# EdgeRelay 运维流程文档

面向：接手这个项目的自己（三个月后忘了细节时）、以及需要排查线上问题的时刻。

配套文档：`README.md` 是「这是什么 + 接口怎么用」，本文档是「怎么操作 + 出事怎么办」。

---

## 1. 系统全貌

三个仓库协作，一条链路：

```
┌─────────────────────┐
│ jian_box（安卓 APP）│
│  cnb.cool + GitHub  │
└──────────┬──────────┘
           │ 1. 上传 APK（拿预签名 URL 直传）
           │ 2. 发起构建
           │ 3. 轮询状态
           ▼
┌─────────────────────┐        ┌──────────────────────┐
│ EdgeRelay 网关       │───────▶│ apk-protect-action   │
│ Cloudflare Worker    │ 4. 触发 │ GitHub Actions 加固   │
│ zzgs219G/EdgeRelay   │        │ 产物上传到 R2         │
└──────────┬──────────┘        └──────────┬───────────┘
           │                               │
           │ 5. 读产物链接（注解/artifact） │
           ▼                               ▼
      ┌─────────────────────────────────────┐
      │ Cloudflare R2（cloud-r2 桶）        │
      │ 公开域名 r2.614118.xyz              │
      └─────────────────────────────────────┘

┌─────────────────────┐
│ zzgs219G/json        │  数据仓库：配置加密包 + schema 镜像
│  gitee 镜像对外      │
└─────────────────────┘
```

**关键设计**：所有凭证（GitHub Token、R2 密钥）只在网关里。
APP 和公开 JSON 里都拿不到。

## 2. 日常操作

### 2.1 发布新版本 APP 配置（改云端 JSON）

配置明文在 `zzgs219G/json` 仓库的 `backend/jian_box/raw/配置.json`。

改了之后必须**重新加密**，因为 APP 读的是 `.enc` 不是明文：

```bash
# 1. 改明文
vi backend/jian_box/raw/配置.json

# 2. 加密（Python 复刻 AesTool.kt 的算法）
python3 - <<'PY'
import json, io, os, base64
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC
from cryptography.hazmat.primitives import hashes

PASSWORD = b"zzgs219"      # 与 AppSecrets.kt 一致
ITERATIONS = 10000         # 与 AppSecrets.kt 一致

def derive_key(salt):
    return PBKDF2HMAC(algorithm=hashes.SHA256(), length=32,
                      salt=salt, iterations=ITERATIONS).derive(PASSWORD)

plain = io.open("backend/jian_box/raw/配置.json", encoding="utf-8").read()
json.loads(plain)                      # 先验 JSON 合法

salt, iv = os.urandom(16), os.urandom(12)
ct = AESGCM(derive_key(salt)).encrypt(iv, plain.encode(), None)
enc = base64.b64encode(salt + iv + ct).decode()

io.open("backend/jian_box/jian_box.enc", "w").write(enc)
print("已生成，%d 字符" % len(enc))
PY

# 3. 提交（.enc 和明文一起改，明文作为源便于以后维护）
git add backend/jian_box && git commit -m "config: 更新云端配置" && git push
```

> ⚠️ `AES_PASSWORD` / `AES_ITERATIONS` 必须与 APP 的 `AppSecrets.kt` 完全一致，
> 否则 APP 解不开会静默回退到内置兜底配置。

### 2.2 改网关配置（不用重新部署）

浏览器打开 `https://<网关域名>/`，用 `RELAY_PASSWORD` 登录，进「配置」页。

四张卡片：

| 卡片 | 改什么 |
|---|---|
| GitHub | Token、owner/repo、分支 |
| R2 存储 | S3 端点、桶名、Access Key、Secret Key、公开域名 |
| 访问凭证 | `RELAY_TOKEN`（APP 用）、`RELAY_PASSWORD`（面板用） |
| 运行时参数 | 限流、任务保留天数、等 run_id 上限 |

**改完立即生效**（存 KV），不用 `wrangler deploy`。

**逃生舱**：`RELAY_PASSWORD` 改了之后，CF secret 里的旧密码**仍然有效**。
万一在 UI 里打错或忘了，用旧密码登进去改回来。

### 2.3 改加固模块（schema）

改 `apk-protect-action` 的 `configs/v1/config-schema.json` → push。

链路会自动跑：

```
push configs/**
  → Notify json mirror（apk-protect-action 侧）
  → repository_dispatch: apk-schema-updated
  → APK Schema Mirror（json 仓库侧）
  → 拉取 → 提交 backend/apk_schema/v1/config-schema.json
```

APP 从 gitee 镜像读，**不用发新版**。

**如果 dispatch 没触发**（PAT 过期等），手动补：

```
GitHub → zzgs219G/json → Actions → APK Schema Mirror → Run workflow
```

### 2.4 部署网关

**当前由 Cloudflare Workers Builds 负责**（CF 控制台连 Git，push 自动部署）。

控制台配置（Worker → Settings → Build）：

| 字段 | 值 |
|---|---|
| Build command | 留空 |
| Deploy command | `npm run deploy` |

> `npm run deploy` 内部会先装前端依赖、跑 vite build，再 `wrangler deploy`。
> **不能填 `npx wrangler deploy`** —— 那样不构建前端，会报 assets 目录不存在。

GitHub Actions（`.github/workflows/ci.yml`）**只做质量门，不部署**：
tsc + 99 个测试 + 前端构建 + dist 同步校验。

## 3. 自检清单

出问题时按顺序查，先排除最常见的。

### 3.1 网关是否活着

```bash
curl https://<网关域名>/health
```

响应里的字段含义：

| 字段 | 说明 |
|---|---|
| `ok` | `true` = KV 正常，面板可用 |
| `kv` | `ok` / `error` |
| `problems` | **致命**问题（KV 不可用），会导致 503 |
| `missing` | 会导致**构建失败**的缺失项（如 `GITHUB_TOKEN`） |
| `warnings` | 非致命，如「`RELAY_TOKEN` 未配置，APP 无法调用」 |

`ok: true` 但 `warnings` 非空 = 面板能用，部分功能缺失。这是正常的中间状态。

### 3.2 APP 报「网关未配置」

APP 从云端 JSON 读 `云服务配置.网关地址` 和 `云服务配置.网关令牌`。

```bash
# 解密后确认这两个字段有值
# （按 §2.1 的方式解密 jian_box.enc）
```

常见原因：
- 改了明文 JSON 但忘了重新加密
- 加密参数的 `AES_PASSWORD` / 迭代次数与 APP 不一致
- APP 用了缓存的旧配置（杀掉进程重开，或清应用数据）

### 3.3 APP 上传 APK 失败（503 R2 未配置）

面板「配置 → R2 存储」四项填齐：

| 面板字段 | 从哪取 |
|---|---|
| S3 端点 | Cloudflare R2 页面右上角，形如 `https://<account>.r2.cloudflarestorage.com` |
| 存储桶名 | 你的桶名 |
| Access Key ID | R2 → Manage R2 API Tokens |
| Secret Access Key | 同上（只显示一次） |

### 3.4 构建显示「处理中」很久

按 `job_id` 查状态：

```bash
curl https://<网关域名>/api/status/<job_id> \
  -H "Authorization: Bearer <RELAY_TOKEN>"
```

| `app_status` | 含义 | 下一步 |
|---|---|---|
| `PENDING` | 还没绑上 GitHub run_id | 等 cron（1 分钟）或看 §3.5 |
| `PROCESSING` | 流水线在跑 | 去 GitHub Actions 看实际进度 |
| `SUCCESS` | 完成，`download_url` 可用 | — |
| `FAILED` | 失败，看 `error` 字段 | — |

查步骤明细定位卡在哪一步：

```bash
curl https://<网关域名>/api/status/<job_id>/steps \
  -H "Authorization: Bearer <RELAY_TOKEN>"
```

### 3.5 任务永远 PENDING（run_id 绑不上）

网关 dispatch 后会用 `created_at` 匹配新 run。绑不上说明：

- GitHub 那边的 run 创建时间比网关记录的早超过 90 秒（时钟偏差）
- 同名 workflow 有并发 run，匹配到了别人的

排查：

```bash
# 看这个 workflow 最近的 run
gh run list --repo zzgs219G/apk-protect-action --workflow=protect-modules.yml --limit 5
```

如果确认某个 run 就是这次构建的，但网关没绑上——目前没有手动重绑接口，
只能等 cron 重试（1 分钟一次，最多试到 `JOB_RETENTION_DAYS` 过期）。

## 4. 常见报错的含义

### 部署相关

| 报错 | 原因 | 修法 |
|---|---|---|
| `KV namespace 'XXX' is not valid` | `wrangler.toml` 的 `id` 是占位符 | `wrangler kv namespace create EDGE_RELAY_KV` 后填入 |
| `Can't set compatibility date in the future` | `compatibility_date` 晚于构建机当前日期 | 改早一点，它只看构建机时钟 |
| `Expected "routes" to be an array...` | `workers_dev` 写在了 `[[routes]]` 之后 | TOML 里顶层键必须放在所有表之前 |
| `assets.directory does not exist` | 没构建前端 | Deploy command 用 `npm run deploy` |
| `Cannot find package '@vitejs/plugin-vue'` | Build command 填了但没装前端依赖 | Build command 留空，全交给 `npm run deploy` |

### APP 相关

| 报错 | 原因 |
|---|---|
| `Imported HMAC key length (0)` | `RELAY_TOKEN` 没配（已修：现在面板登录不依赖它） |
| `RELAY_TOKEN 未配置` | 同上 |
| 401 无效或缺失的 Bearer 令牌 | APP 的 `网关令牌` 与网关的 `RELAY_TOKEN` 不一致 |
| `key 必须以 apks/ 开头` | 预签名时 key 前缀不对（APP 侧 bug） |

## 5. 安全模型与轮换

### 5.1 凭证放哪

| 凭证 | 位置 | APP 能拿到吗 |
|---|---|---|
| `GITHUB_TOKEN` | Worker secret 或面板 KV | ❌ |
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` | Worker secret 或面板 KV | ❌ |
| `RELAY_TOKEN` | Worker secret 或面板 KV | ✅（APP 需要它调网关） |
| `RELAY_PASSWORD` | 仅 Worker secret / KV | ❌ |

**`RELAY_TOKEN` 是唯一下发到 APP 的凭证**。它只能调网关的接口，
拿不到 GitHub / R2。泄漏后的止损方式是轮换它（见下）。

### 5.2 轮换 `RELAY_TOKEN`

1. 面板「配置 → 访问凭证」填新值并保存
2. 重新生成 APP 的云端配置（§2.1），`网关令牌` 填同一个新值
3. 推 `json` 仓库，APP 下次拉配置时生效

**旧值在过渡期仍然有效**（双通道设计），所以正在跑的 APP 不会立刻断。

### 5.3 轮换 `RELAY_PASSWORD`

面板里直接改。CF secret 里的旧密码仍然有效——这是故意的逃生舱。

要彻底作废旧密码，去 CF 控制台 `wrangler secret put RELAY_PASSWORD` 改成新值。

### 5.4 轮换 R2 密钥

1. Cloudflare R2 → Manage R2 API Tokens → 建新 token
2. 面板「配置 → R2 存储」填入新 key
3. 回 R2 控制台删旧 token

> 改动需在面板点「保存」，会立即生效。正在上传的任务需重试。

## 6. 恢复操作

### 6.1 网关完全不可用

```bash
# 1. 确认是 KV 挂了还是 Worker 没起来
curl https://<网关域名>/health

# 2. 看实时日志
npx wrangler tail

# 3. 回滚到上一个版本
npx wrangler deployments list
npx wrangler rollback <deployment-id>
```

### 6.2 面板密码忘了

用 CF secret 里的旧密码（逃生舱）。如果两个都忘了：

```bash
npx wrangler secret put RELAY_PASSWORD   # 重设
```

### 6.3 APP 配置全部错了

APP 有本地兜底（`assets/config.json`）。最坏情况下重新打包 APP，
或者确保云端 `.enc` 能被正确解密。

### 6.4 任务表被污染

任务存在 KV 的 `job:` 前缀下，可以手动删：

```bash
npx wrangler kv key list --binding=EDGE_RELAY_KV --prefix="job:"
npx wrangler kv key delete --binding=EDGE_RELAY_KV "<key>"
```

## 7. 已知限制

| 限制 | 影响 | 缓解 |
|---|---|---|
| KV list 免费额度仅 1000/天 | 面板轮询过于频繁会打爆 | 已加 15s 后端缓存 + 前端只在有在途任务时轮 20s |
| GitHub dispatch 不返回 run_id | 需另行匹配，有极低概率绑错 | 用 `created_at` 过滤 + cron 重试 |
| R2 预签名 10 分钟过期 | 大文件慢网络可能传不完 | 超时重试即可（重新申请 URL） |
| 本机跑不了 `assembleDebug` | jian_box 只能验证到 Kotlin 编译 | 资源打包/APK 产物需在 CI 或 PC 验证 |
| `wrangler deploy` 不构建前端 | 直接部署会报 assets 不存在 | Deploy command 用 `npm run deploy` |
